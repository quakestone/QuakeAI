## 0. 一句话

## 2. 作用域页（`#/models`，标题「模型管理」）

```
模型管理
──────────────────────────────────────
[概览] [模型] [提示词] [用量] [积分榜]
```

### 2.0 页头：只留四个字

现在的页头是 `← ☰ 模型管理 / 资源管理 · 智能路由 · 国内优先 ……… store: ok [＋ 登记资源]`，一屏宽度被切成六七段。改成**一行纯文字**：

| 元素 | 处理 |
|---|---|
| `←` 返回键 | **删** |
| `☰` 侧栏键 | **删**（左缘右滑仍可开侧栏，手势不变） |
| 副标题「资源管理 · 智能路由 · 国内优先」 | **删**（这三句本来也没有信息量） |
| `store: -` 徽标 | **删**；账本异常时改由内容区顶部那条 `store-banner` 红条承担，正常态一个字都不显示 |
| `＋ 登记资源` | **删**（§1 已定，登记去设置页） |
| `spacer` / 底部分隔线 / sticky 背景 | **删**：页头不再是吸顶条，随页面滚走 |

视觉规格：

```
.mgmt-top.bare {
  display:block; position:static; border:none; background:none;
  padding: 18px 16px 8px;        /* 顶部安全区照旧 env(safe-area-inset-top) */
}
.mgmt-top.bare .ttl { font-size:17px; font-weight:700; letter-spacing:.2px; }
```

- 左对齐，与下方标签栏、卡片左缘同一条竖线（16px）。
- 标题下方到标签栏留 6px，标签栏上方**不加**额外分隔线——靠留白分段，不靠线。
- 滚动后标题正常滚走，不吸顶。这一页是"看"的页面，不是操作台，不需要常驻工具条。

**返回怎么走**（撤掉 ← 之后不能把人困住，三处兜底）：

1. **标题即返回**：整行 `.ttl` 是热区，点击 `navigate('chat')`（`cursor:pointer`，`title="返回聊天"`，无任何视觉标记——看上去就是四个字）。
2. 浏览器 / WebView 系统返回键，落到聊天页。
3. 左缘右滑开侧栏，从会话列表回去。

从选择器 ⚙ 进来的场景仍走 §4 的 `pendingPickerReturn`：路由离开 `#/models` 时若该标记存在，自动重开选择器并停在原 tab。

> 如果你连"标题可点"都不想要（纯静态文字），说一声——那就只靠系统返回键，代价是 iOS 上要够到底部工具栏。

5 个标签在 390px 下每栏约 70px，标签文案控制在 2–3 字（13px），不出省略号。

原副标题里那句「文本 · 当前 glm-4-flash」不丢，挪进概览卡卡头——页头不承担状态显示。

## 3. 设置页（`#/settings`）

### 3.1 结构：一个容器 + 分区切换

不写 7 个独立 HTML 文件，也不做一根长条。做法：

```
#view-settings
  <header class="mgmt-top">  ← ‹ 返回 · 标题（随分区变） · 副标题
  #sect-list        ← 菜单（#/settings 无分区时显示）
  #sect-registry    ← 模型登记
  #sect-keys        ← 模型换 Key
  #sect-mm          ← 多媒体配置
  #sect-wf          ← 工作流参数
  #sect-api         ← 接入方式
  #sect-auth        ← 管理面鉴权
```

设置页沿用作用域页那套极简视觉（一行标题、无吸顶条、无分隔线），但**保留 `‹` 返回**：分区 → 菜单 → 聊天是两级，少了这个键就得连按两次系统返回。作用域页是一级，所以能裸。其余 `☰`、副标题、徽标、按钮一律不要。

路由 `#/settings/<sect>` 决定显示哪一段，其余 `hidden`。视觉上是各自独立子页（都有标题和返回键），代码上共用一份 `CHANNELS` 和一套加载逻辑。

### 3.2 菜单（`#/settings`）

侧栏 ⚙ 直接落到这里 —— 这就是你说的"设置按钮子菜单"：

| 菜单项 | 副标题 | 去往 |
|---|---|---|
| 📦 模型登记 | 已登记资源 · 分页浏览 · 新增 · 预设 · 设备 Key | `#/settings/registry` |
| 🔑 模型换 Key | 缺 Key / 失效渠道的待办队列 | `#/settings/keys` |
| 🎛 多媒体配置 | STT / TTS / 视觉 / 视频 四路映射 | `#/settings/mm` |
| 🧩 工作流参数 | 用量记账 · 自动标题 · 记忆压缩 · 版式 | `#/settings/wf` |
| 🔌 接入方式 | OpenAI 兼容端点与响应头 | `#/settings/api` |
| 🔐 管理面鉴权 | ADMIN_TOKEN | `#/settings/auth` |
| 🩺 部署自检 | 绑定 / 存储 / 版本 | 直接开 `diag-dlg` |

菜单项只写**名字 + 一句副标题**，不放开关、不放统计数字——设置菜单的职责是"去哪里"，不是"告诉你状态"。状态在各自分区里。

### 3.3 模型登记（`#/settings/registry`）

**分页主体：已登记资源，每页 2 张大 banner。**

```
‹  模型登记
────────────────────────────────────────
已登记资源 12 · 有 Key 9 · 缺 Key 3      [＋ 登记] [⋯]
[全部 12] [缺 Key 3] [已停用 1]
────────────────────────────────────────
 ‹  ┌──────────────────────────────┐  ›
    │ ● 智谱 GLM 主线      [文本][T1]│
    │   zhipu · glm-4-flash · 3 模型 │
    │   Key 已配置 · 可用 · 12 分钟前 │
    │   [编辑] [换 Key] [测试] [⋯]   │
    ├──────────────────────────────┤
    │ ● 通义千问 主线      [文本][T2]│
    │   dashscope · qwen-max · 2 模型│
    │   缺 Key · 未自检              │
    │   [编辑] [换 Key] [测试] [⋯]   │
    └──────────────────────────────┘
         ● ● ● ○ ○ ○        2 / 6
────────────────────────────────────────
▸ 从预设快速登记（国内 11 + 海外 3）
▸ 本设备 Key
▸ 降权 / 切换事件（最近 50 条）
```

**分页规则**

| 项 | 规则 |
|---|---|
| 每页条数 | 固定 **2 张**，不按高度自适应——一页两张、一屏正好，节奏一致 |
| 排序 | 缺 Key → 降权/冷却中 → 正常 → 已停用（置底灰显） |
| 页码形态 | ≤8 页用圆点；>8 页显示 `2 / 13` + 首末跳转 |
| 翻页 | 左右箭头 + 横向滑动（阈值 48px）+ 键盘 `←` `→` |
| 记忆 | 当前页存 `sessionStorage`，按筛选 key 分开记；刷新回到原页 |
| 筛选切换 | 回第 1 页（否则容易停在空页） |
| 删除渠道 | 当前页空了就退一页；只剩 1 页时隐藏箭头与圆点 |
| 渲染 | 翻页只替换这两张卡的 DOM，不整块重渲染——否则会闪一下并跳回顶部 |

**卡片内容**：沿用现有渠道卡，四件事不变（编辑 / 换 Key / 测试 / ⋯删除）。宽度从「列表里的一行」变成「独占一屏宽」，所以信息可以摊开：来源 · 模型名 · 模型数 · Key 状态 · 可用性 · 上次自检时间。

**顶部那行统计**不是五个格子，压成一句话：`已登记资源 12 · 有 Key 9 · 缺 Key 3`。分页之后一屏只放得下两张卡，再来五个统计格子会把卡挤到折叠线以下。

**工具条**：`＋ 登记` 常驻列表标题行右侧（唯一主操作，不能藏）；`⋯` 收「一键载入默认 / 导出配置 / 部署自检」——这三个是低频动作，不值得占一行。

**底部折叠**：预设快速登记、本设备 Key、降权事件。它们回答"还能不能持续用"，是登记前后的辅助信息，不占分页位。

### 3.4 模型换 Key（`#/settings/keys`）

这页**不再重复全量列表**——渠道卡已经在模型登记里分页看过了，再来一遍只是同一批数据换个地方摆。

改成**待办队列**，只列两类：

- 从没配过 Key 的渠道
- 最近事件里出现 401 / 403 / `invalid_api_key` 的渠道

```
‹  模型换 Key
────────────────────────
3 个渠道需要处理
┌──────────────────────┐
│ 通义千问 主线  缺 Key  │  [换 Key]
├──────────────────────┤
│ 某海外渠道    Key 失效 │  [换 Key]
└──────────────────────┘
[查看全部渠道 →]
```

行是紧凑单行，不是大卡——这里的主任务是"逐条补 Key"，不是"浏览"。补完一条就从队列消失，空了显示"12 个渠道都有可用 Key"。

「换 Key」直接弹输入框（复用现有 `key-dlg`），保存后原地移除该行，不整页刷新。

### 3.5 多媒体配置（`#/settings/mm`）

常驻：现有 `#mm-card` 的"两块独立配置"（STT / TTS / 视觉 / 视频 / 范围），原样搬过来。

下面加一个折叠「高级（模式 / 端点 / 音色 / 语速）」，把 `voice-dlg` 的字段并进来：

- TTS 模式（auto / gateway / custom / browser）+ **新增**「网关失败时仍用浏览器语音」开关
- 自定义 TTS 端点（URL / Key / 模型 / 音色）
- 浏览器音色、语速
- STT 模式

**统一成一个 `saveVoiceCfg()`**。现在 `#mm-card` 用 `saveMgmtMm()`、`voice-dlg` 用 `vg-save`，两份都写 `gw_voice_cfg` 但字段集不同，改一处忘一处就会互相覆盖。合并后 `voice-dlg` 保留为快捷入口（选择器的 🎛、通话页），内部调同一个保存函数。

### 3.6 其余分区

- `#sect-wf`（**工作流参数**）：现有 `wf-fold` 内容原样搬——用量统计、自动标题、记忆压缩、附件版式、标题/记忆模型、缩略图与视频容器尺寸、当前会话记忆。标题从「⚙ 工作流引擎（浏览器侧 WASM）」改成「工作流参数」，副标题保留"浏览器侧 WASM · 本地执行、服务端零存储"。
- `#sect-api`：现有 curl 代码块
- `#sect-auth`：ADMIN_TOKEN 输入

工作流这块原本是页面最底部的折叠，几乎没人会滚到那里。挪进设置子菜单后反而更容易被找到——它本来就是个"配一次就不动"的参数页。

## 5. TTS 兜底优化（B 的附带项）

你说"呼叫页 AI 一直播放不了，tts 为默认绑定"。先把现在的链路摆出来，再改。

### 5.1 现在怎么走的

`ttsMode` 默认 `"auto"` → 每句先打 `/v1/audio/speech` → 失败才降级浏览器语音。

静态能确认的四个薄弱点：

1. **网关没有 tts 能力模型时**，`pick_model_attempts` 返回空 → `no_candidates_response` 503 `no_candidate_model`。每句话都要先吃一次这个 503。
2. **浏览器兜底失败时，错误被"还原"成网关错误**：`ttsPlaySentence` 里 `if (!BrowserTts.ready) throw e;` —— 抛的是网关那条"请登记 TTS 模型"，用户完全看不出真正断的是浏览器语音（设备无音色 / voices 未加载）。
3. **降级提示是一次性 toast**（`ttsDegradeNotified`），通话页全屏时基本看不到。
4. **`ttsBlob` 没有超时**，上游卡住时通话静默等待，既没"合成中"也没"失败"。

### 5.2 改法（四条）

**① 熔断：配置性失败一次就切，不再每句重试**

区分两类失败：

| 类型 | 判定 | 策略 |
|---|---|---|
| 配置性 | 503 `no_candidate_model` / 404 / 401 | **本次通话立刻熔断**，后续句子直接走浏览器语音 |
| 临时性 | 超时 / 5xx / 网络 | 连续 2 次才熔断，单次失败仍重试 |

熔断状态存 `ttsCircuit = { open, until, reason }`，挂断时重置。这样"没配 TTS 模型"的用户第一次点播放会等一次 503（几百毫秒），之后整个通话零等待。

**② 最后一层兜底不再抛错**

- `gateway` 模式（原本"不降级"）加开关「网关失败时仍用浏览器语音」，**默认开** —— 这就是你要的"拖底"。真正的"仅网关不降级"变成显式选择。
- 三层全断时，日志给一句人话 + 一个可点动作：
  `播报失败：本机没有可用语音，网关也没有 TTS 模型 → [去配置]`

**③ 让链路可见**

- 通话页顶栏加徽标：`网关播音` / `浏览器语音`，切换时闪一下。
- 多媒体配置加「测试播报」按钮，逐层输出：网关 HTTP 状态 + 字节数 / 失败原因 / 浏览器音色数 / 是否真的发声。一次点击就能定位断在哪层，不用再靠猜。

**④ 预热与超时**

- 进通话页时（手势内）就跑 `BrowserTts.init()`，别等第一句失败后再等 1.5s 轮询。
- `ttsBlob` 加 8s 超时（`AbortSignal.timeout`），按临时性失败计。

### 5.3 默认值

`ttsMode` 保持 `auto`，但多媒体配置里加一次**静默探测**：打开页面时发一个 6 字的短句到网关（不发声），把结论写进 `voiceCfg.ttsProbe = { ok, at, reason }`，在四路映射上方直接标：

```
TTS 链路：网关可用（glm-tts · 820ms）     ← 绿
TTS 链路：网关不可用（未登记 tts 模型）→ 自动走浏览器语音   ← 黄
```

这条比"等用户点播放才发现"省事，也让"为什么一直播不了"有据可查。

## 7. 五个必然踩到的 bug

1. **停用后消失**（§2.2）—— 功能性缺陷，不是样式问题。
2. **`renderChannels()` / `loadAll()` 无 null 守卫** —— 拆页后直接白屏。
3. **`/admin` 默认落 models**（§4）—— 拆分后语义错位。
4. **`#store-badge` 被删但两处仍在赋值**（4534 / 4857 行）—— 页头极简的连带伤，进页面即 TypeError，整页脚本停在加载中。
5. **分页 + 排序会越界**：删掉第 6 页仅剩的那张卡后，`page=6` 但只有 5 页，屏幕空白且箭头点不动。每次重排后都要 `page = min(page, pageCount)`，且 `pageCount` 最少为 1。
