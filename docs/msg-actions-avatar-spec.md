## 第 3 条：AI 回答操作按钮回退到 v0.19.10 的形态

### 现在是什么样

v0.19.11 把助手的行内操作压缩成两个：

```
[模型 xxx] [05:43]  🔊 播音   ⋯
```

`复制`、`分享`、`重新生成`、`删除` 全部收进了「⋯」菜单。当时的理由是「行内按钮太多，
窄屏会挤成两行」。实际用起来的问题是：**复制和分享是最高频的两个动作，现在都要多点一次**，
而且「⋯」里到底有什么，不点开看不见。

### 回退成什么样（v0.19.10 原样）

```
[模型 xxx] [05:43]  复制  分享  🔊 播音   ⋯
```

- `复制` `分享` `🔊 播音` 三个文字按钮直接排在 meta 行，字号 11px、`padding: 1px 6px`、
  hover 变 `--panel2` 底色 —— 这套 `.msg-meta .act-btn` 样式**现在还完整保留在文件里**
  （第 129–133 行），只是没人用了，回退不需要新增 CSS。
- `⋯` 仍然留在行尾（`margin-left: auto` 推到最右），因为它承担的是「不常用动作」的入口。

### 菜单要去重

行内已经有复制/分享，菜单里再放一遍就是同一个动作两个入口，用户会怀疑「哪个才算数」。
所以菜单按角色拆开：

| 菜单项 | 用户消息 | 助手消息 | 说明 |
|---|---|---|---|
| 复制 | ✅ | ❌ | 助手行内已有 |
| 修改 | ✅ | ❌ | 仅用户 |
| 重试 | ✅ | ❌ | 仅用户 |
| 强调 | ✅ | ❌ | 仅用户 |
| 重新生成 | ❌ | ✅ | 仅助手 |
| 分享 | ❌ | ❌ | 助手行内已有，菜单项直接删掉 |
| 删除 | ✅ | ✅ | 两边都留 |

实现：`#mm-copy` 加 `class="mm-user"`，`#mm-share` 从 DOM 删除（`menuShare()` 函数保留，
行内按钮直接调它）。`openMsgMenu()` 里那两行 `mm-user` / `mm-asst` 的显隐逻辑不用改。

### 流式期间与错误消息

- 生成中（`m.streaming`）行内整排不渲染 —— 和现在一致，避免点「复制」拿到半截内容。
- 出错消息（`.msg.error`）行内只保留 `⋯`，不显示复制/分享/播音（没有内容可复制）。

### 窄屏行为（390px 实测预判）

一行放不下 `模型 xxx + 时间 + 复制 + 分享 + 播音 + ⋯`，`.msg-meta` 已经是 `flex-wrap: wrap`，
会折成两行：第一行徽章+时间，第二行三个按钮+⋯。v0.19.10 就是这样，可接受。
若嫌按钮行太散，把 `gap` 从 10 收到 6，按钮 `padding` 从 `1px 6px` 收到 `1px 4px`。

## 第 5 条：用户几何头像再放大

### 现状与问题

| | 圆框 | 图形 | 描边 |
|---|---|---|---|
| 助手 | 30px | 「AI」13px 文字 | — |
| 用户 | 34px | svg 24px | 1.8 |
| 用户（窄屏） | 30px | svg 21px | 1.8 |

框已经比助手大 4px，但**视觉上仍然显小**：助手是 30px 实心渐变圆，色块铺满；
用户是空心细线，只有线条本身有重量，24px 的线框放在 34px 的圆里，四周留白吃掉了一部分体量。
这就是「看着比 AI 小」的原因——不是尺寸数字的问题，是**填充率**的问题。

### 目标数值（推荐 A 档）

| | 圆框 | 图形 | 描边 | 填充率 |
|---|---|---|---|---|
| 助手 | 30px | 13px 字 | — | 实心 100% |
| 用户 | **38px** | **28px** | **2.0** | 54% |
| 用户（窄屏 <420px） | **34px** | **25px** | 2.0 | 54% |

三个一起动，缺一不可：

1. **框 34 → 38**：给 28px 图形留出均匀的 5px 边距，不顶边。
2. **图形 24 → 28**：这是真正让它"变大"的一步，面积增加 36%。
3. **描边 1.8 → 2.0**：放大后线条相对变细，1.8 会显得发飘、发灰；2.0 才撑得住。

窄屏同步按比例缩放（38/28 → 34/25），保持和助手 26px 的比例关系。

### 备选 B 档（更夸张）

框 **42px** / 图形 **31px** / 描边 2.2，窄屏 38/28。视觉上和助手拉开明显差距，
代价是用户消息行高增加约 8px，且正文左边距被吃掉 8px（390px 屏下正文宽度从 316 降到 308）。

**推荐 A 档**：足够看出"用户比 AI 大一档"，又不至于把消息行撑成两个不同节奏。

### 副作用

- 用户消息行高 +4px（A 档），与助手消息的行高差从 4px 变成 8px。因为用户消息右对齐、
  助手左对齐，两边不在同一视觉列上，不会显得歪。
- 头像变大后，`.msg { gap: 10px }` 保持不变——gap 是头像与气泡之间的距离，与头像尺寸无关。
- 若之后加"助手也用几何图形"的改动，这套比例要重新算。
