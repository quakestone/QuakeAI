## 3. 模型行布局：从「单行挤」改成「两行稳」

**问题复现**（图一）：

```
cohere/north-        ← 名称被挤成 4 行
mini-
code:free  [文]      ← 能力徽章被顶到下一行，且「文本」被竖排成 文/本
         OpenRouter（海外兜底）· openrouter · T0 · 积分 7   ← meta 撑出屏幕，积分被切
```

**根因**：`.model-opt` 是单行 flex。名称容器没有 `min-width:0`，会按内容撑开并换行；meta 是 `white-space:nowrap` + `margin-left:auto`，宽度不够直接溢出。名称长度不齐时徽章位置前后跳动。徽章本身也没 `white-space:nowrap`，被压到极限时文字竖排。

**方案**：改两行结构，不再依赖单行对齐。

```
┌──────────────────────────────────────────┐
│ cohere/north-mini-code:free （检测中…） 文 │  ← 名称省略 + 括号 + 徽章贴右
│ OpenRouter（海外兜底）· openrouter · 积分 7 │  ← meta 省略
└──────────────────────────────────────────┘
```

```css
.model-opt { display: flex; flex-direction: column; align-items: stretch;
             gap: 3px; padding: 9px 11px; min-width: 0; }
.model-opt .mo-row1 { display: flex; align-items: center; gap: 6px; min-width: 0; }
.model-opt .mo-name { flex: 0 1 auto; min-width: 64px; overflow: hidden;
                      text-overflow: ellipsis; white-space: nowrap; font-weight: 600; }
.model-opt .avail-br { flex: 0 1 auto; min-width: 0; overflow: hidden;
                       text-overflow: ellipsis; white-space: nowrap; }
.model-opt .cap-badge { flex: none; margin-left: auto; white-space: nowrap; }  /* 关键：不换行不竖排 */
.model-opt .mo-meta { font-size: 11px; color: var(--dim);
                      overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }
```

四条硬约束：

1. **徽章永不换行、永不竖排、永不溢出**（`flex:none` + `nowrap` + 贴右），名称再长也只压名称。
2. **名称最多一行**，超长省略，`title` 挂全名。
3. **meta 最多一行**，超长省略，不再出现积分被切一半。
4. 行高稳定：名称 11 字符还是 25 字符，行高一致。

同时删掉旧的 `.model-opt .p { white-space:nowrap; margin-left:auto }`（`:524`），`renderModelList()`（`:3732-3747`）HTML 随之调整，「自动」行同样走两行结构。

## 7. 标签栏改成真正的分栏（图一）

### 7.1 为什么现在"不像标签页分栏"

`:139-142`

```css
.tabbar { display:flex; gap:6px; margin:4px 0 12px; overflow-x:auto; }
.tabbar .tab { flex:none; padding:7px 14px; border-radius:999px; white-space:nowrap; }
```

三个原因叠加：

1. **视觉语言错了**：每个标签是独立的**胶囊按钮**（圆角 999px + 边框 + 填充），看起来是"4 个按钮排一排"，不是"一个控件被分成 4 栏"。
2. **宽度不等**：`flex:none` + `padding:7px 14px` → 宽度跟着文案长度走（`💬 文本模型` 和 `🧩 skill 模型` 宽度不同），左边缘参差。
3. **被截断**：`overflow-x:auto` + 总宽超出容器 → 第 4 个「🖼 图视模型」永远只露一条边（图一右侧那个绿边）。

### 7.2 改成等宽分栏 + 底部指示条

```css
.tabbar {
  display: grid;
  grid-auto-flow: column;
  grid-auto-columns: minmax(0, 1fr);   /* 4 个或 5 个都自动等分，不用两套规则 */
  gap: 0;
  margin: 2px 0 12px;
  border-bottom: 1px solid var(--border);
  overflow: visible;                    /* 不再横滚，杜绝半截标签 */
}
.tabbar .tab {
  position: relative;
  height: 38px; min-height: 0;
  padding: 0 4px;
  border: none; border-radius: 0; background: transparent;   /* 去掉胶囊 */
  color: var(--dim);
  font-size: 12px; font-weight: 500;
  white-space: nowrap; overflow: hidden; text-overflow: ellipsis;
}
.tabbar .tab:hover { color: var(--txt); background: transparent; }
.tabbar .tab.sel { color: var(--txt); font-weight: 600; background: transparent; }
.tabbar .tab.sel::after {              /* 选中 = 底部 2px 指示条，这才是"分栏" */
  content: ""; position: absolute; left: 10%; right: 10%; bottom: -1px; height: 2px;
  border-radius: 2px 2px 0 0; background: var(--acc);
}
```

要点：**等宽**（`1fr` 均分）、**同高**（固定 38px）、**无边框无圆角**、**选中靠底部指示条而非填色**、**不横滚**。这四件事做完，才读得出"分栏"。

## 8. 出口统一：只留返回键 + 边缘滑动

### 8.1 现状盘点（比预想的好）

7 个 dialog **都已有** `.dlg-back` 返回键（`:964/981/1009/1024/1035/1061/1132`）。全局手势 `bindEdgeSwipe`（`:1258-1300`）**已实现**「左缘 24px 内起手右滑 > 56px → 关闭最上层 dialog」。

真缺的是两件：

| 缺口 | 具体 |
|---|---|
| **重复出口** | 3 处底部「关闭」按钮：`model-dlg`（`:1057`）、`diag-dlg`（`:1151`）、`voice-dlg`（`:1125` 第二个按钮） |
| **手势无反馈** | 滑动过程中界面完全不动，用户不知道这个手势存在，也不会去用 |

### 8.2 改动

**A. 删除重复出口**

| 位置 | 处理 |
|---|---|
| `:1057` | `<div class="dlg-actions"><button onclick="modelDlg.close()">关闭</button></div>` 整行删除 |
| `:1151` | `diag-dlg` 同上，整行删除 |
| `:1125` | `voice-dlg` 的「保存 / 关闭」→ 只删「关闭」，保留「保存」 |

`share-dlg`（`:968`）底部是功能按钮（复制 / 系统分享 / 二维码 / 打开），不是出口，保留。

**B. 手势跟手化**

1. `pointerdown` 在左缘 24px 内 + dialog 打开 → 开始跟手；
2. `pointermove`：`dialog.style.transform = translateX(dx)`，遮罩 `opacity` 同步衰减；
3. `pointerup`：`dx > 96px`（约屏宽 1/4）**或**速度 > 0.5px/ms → 关闭；否则 180ms 回弹；
4. 纵向位移大于横向 → 判定为滚动，放弃手势并复位。

**C. 冲突规避**

弹窗内横向滚动只剩代码块和长表格。`pointerdown` 时检查 `e.target.closest("pre, .content, .tabbar")`，命中则不起手——避免"想滚代码块却把弹窗滑走"。

**D. 保留的出口**

| 出口 | 保留 | 理由 |
|---|---|---|
| 左上返回键 | ✅ | 主出口，所有子页统一 28×28 |
| 左缘右滑 | ✅ | 移动端主出口 |
| Esc | ✅ | 桌面习惯，零成本 |
| 底部「关闭」 | ❌ 删除 | 与返回键重复 |
| 点遮罩关闭 | ❌ 现状就没有 | 维持，避免误触 |

### 8.3 风险

iOS Safari 左缘右滑是系统「后退」，会和页面手势抢。缓解：手势只在 dialog 打开时生效（现状已是）；若真机冲突，边缘宽度 24px → 16px，并给 dialog 内容区加 `touch-action: pan-y`。

## 9. 图二渲染变形：全局 checkbox 样式缺失（真 bug）

### 9.1 现象

图二里「换模型时重置上下文」那段说明文字**竖排成一列**，复选框孤零零挂在最左边，中间一大片空白，整个弹窗被撑得很高。

### 9.2 根因（已定位到具体行）

`:36` 的全局规则**没有排除 checkbox**：

```css
input, select, textarea { font-size:16px; padding:9px 12px; width:100%;
                          border:1px solid var(--border); border-radius:10px; }
```

于是 `:1054` 的

```html
<input type="checkbox" id="ctx-reset-toggle">
```

变成一个**宽度 100%、带 9px 内边距和 10px 圆角的巨型复选框**。它在 `.mp-ctx-toggle`（`display:flex`）里被设为 `flex:none`（`:253`），basis 取 `width:100%` → **独占整行**，把后面的 `<span>` 挤到只剩 1 个汉字宽。中文按字断行，就成了图二那条竖排文字。

这不是孤例，**全部 6 个复选框都中招**：

| 位置 | 用途 |
|---|---|
| `:932/933/934/940` | 工作流四个开关（用量 / 标题 / 记忆 / 附件规格） |
| `:1054` | 换模型时重置上下文（图二） |
| `:4241` | 多媒体模型「启用」 |

`546` 还有一条 `.vg-row select, .vg-row input { width:100% }`，把 `:932-940` 那四个也一起压成 100% 宽。

### 9.3 修复

```css
/* 复选框必须从全局 input 规则里摘出来：它不该有 100% 宽、内边距和输入框圆角 */
input[type="checkbox"], input[type="radio"] {
  width: 16px; height: 16px;
  flex: none; padding: 0; margin: 0;
  border: 1px solid var(--border); border-radius: 4px;
  accent-color: var(--acc);
  vertical-align: -3px;
}
```

```css
/* :546 同步排除，否则 .vg-row 里的复选框又被拉回 100% */
.vg-row select,
.vg-row input:not([type="checkbox"]):not([type="radio"]) { width: 100%; }
```

```css
/* :253 附近：即使以后布局再变，说明文字也不会塌成一列 */
.mp-ctx-toggle > span { flex: 1; min-width: 0; }
```

### 9.4 为什么必须放在这一版

图二那个变形是**当前线上就存在的渲染 bug**，不是这次改版引入的。它让「换模型时重置上下文」这个开关看起来像坏掉了，用户根本读不懂说明。修它只花一条 CSS，收益最大。

## 10. 用户消息操作：长按 → 气泡内「…」按钮（图三）

### 10.1 现象与成因

长按用户气泡，**两套菜单同时出现**：上面是我们自己的 `#msg-menu`（复制 / 重发 / 删除），下面是 iOS 系统编辑菜单（拷贝 / 查询 / 翻译 / 搜索网页）。

成因在 `bindMsgMenu`（`:1999-2039`）：`pointerdown` 后 500ms 打开自定义菜单，但**没有阻止浏览器默认行为**。长按落在可选中文本上，WebKit 照样弹原生 callout。代码只 `preventDefault` 了 `contextmenu`（`:2021`），而 iOS 的 callout **不走 `contextmenu` 事件**，所以拦不住。

结果：功能有，但被系统菜单盖住、位置还错乱（系统菜单贴手指，我们的在 `y - h - 10`），看起来就像坏了。

### 10.2 方案：入口从「长按」换成「…」按钮

| 项 | 现在 | 改为 |
|---|---|---|
| 触发 | 长按 500ms / 右键 | **用户气泡内「…」按钮**（单击） |
| 位置 | 跟随手指坐标 | 锚定按钮，向下弹出 |
| 菜单项 | 复制 / 重发 / 删除 | **复制 / 修改 / 重试 / 强调** |
| 系统菜单 | 同时弹出 | **不再弹出** |

```css
.msg.user .msg-body { position: relative; }
.msg.user .more-btn {
  position: absolute; top: -2px; right: 0; width: 24px; height: 24px;
  border: none; background: transparent; color: var(--dim);
  font-size: 16px; line-height: 1; padding: 0; border-radius: 6px; opacity: .55;
}
.msg.user .more-btn:hover, .msg.user .more-btn:active { opacity: 1; background: var(--panel2); }
.msg.user .content { padding-right: 30px; }   /* 给「…」留位，避免压住长文本 */
```

常驻可见（移动端没有 hover，不能靠悬停才出现），`opacity .55` 不抢视线。

### 10.3 系统级干扰怎么彻底消掉

```css
.msg.user .content {
  -webkit-touch-callout: none;    /* 关键：禁掉 iOS 长按 callout */
  -webkit-user-select: none;
  user-select: none;
}
```

只作用于**用户气泡**；助手回答保持可选中（代码块要能选、能复制片段）。

代价：用户不能长按选中自己消息里的片段。补偿是菜单里已有「复制」整条，要改内容用「修改」。

### 10.4 四个动作的语义

| 动作 | 行为 | 实现要点 |
|---|---|---|
| **复制** | 复制该条提问全文 | 复用 `menuCopy()`（`:2040`），它取 `.content` 的 innerText |
| **修改** | 气泡原地变 `textarea`，确认后更新内容 → **截断其后所有消息** → 重新请求 | 新增 `editingIdx`；流式中禁用；取消恢复原样 |
| **重试** | **不新增消息**，以该条为最后一条重新请求，截断其后的回答 | ⚠️ 现有 `menuResend()` 对 user 是 `sendWith()` **追加一条**（会重复提问），必须改成截断式 |
| **强调** | 见下，三个候选，需你定 | — |

**「强调」我不猜，你定：**

| 方案 | 行为 | 影响 |
|---|---|---|
| **A（推荐）本地标记** | 气泡左侧 3px 橙色条 + 右上「重点」小徽标，再点取消；**不改请求内容** | 零副作用、可逆；但只是视觉标记 |
| B 加重语气重发 | 原内容后追加「请重点回答这一点」并重试 | 真实改变模型输出，且悄悄改写历史 |
| C 收藏置顶 | 该提问进「重点」列表，会话内可快速回看 | 需要新面板，工作量最大 |

推荐 A：菜单里其它三项都是「对这条消息做什么」，A 与之一致；B 会悄悄改语义，用户不知道模型收到了什么额外指令。

### 10.5 助手消息要不要一起改

| 选项 | 说明 |
|---|---|
| 保持现状 | 助手气泡文本可选中，长按同样弹系统菜单——同一个干扰，只是没被截图 |
| **统一改成「…」** | 助手气泡也加「…」，菜单为 复制 / 重新生成 / 分享 / 播音 / 删除；长按不再触发 |
| 折中 | 助手保留长按（代码块需选中复制），但加 `-webkit-touch-callout:none` 压掉系统菜单 |

建议**统一**：两套交互并存最容易让人困惑；且助手气泡已有「复制 / 分享 / 🔊 播音」三个行内按钮（`:1829`），收进「…」反而更清爽。这条要不要做，你定。

### 10.6 菜单实现

- 复用 `#msg-menu` 容器，内部按角色 `hidden` 切换两组按钮（不维护两套定位逻辑）。
- 定位改**锚定元素**：`place(btn.getBoundingClientRect())`，默认向下，超出视口向上翻转。
- 关闭：点击外部（`:2036` 已有）、Esc、滚动、再次点「…」。

## 11. 用户消息加中性拟人头像

### 11.1 现状：只有助手有头像

```html
<!-- 助手（:1830） -->
<div class="msg assistant"><div class="avatar">AI</div><div class="msg-body">…</div></div>
<!-- 用户（:1818）—— 没有 avatar -->
<div class="msg user"><div class="msg-body">…</div></div>
```

`.msg` 本身已经是 `display:flex; gap:10px`（`:99`），用户消息只是**少了一个子元素**。补上后两条消息骨架对称。

而且用户气泡的圆角本来就是 `14px 14px 14px 4px`（`:105`，左下角收成 4px）—— 这个"指向左下"的收角正是给头像留的视觉缺口，说明原设计就预留了头像位，只是没填。

### 11.2 三个候选

| 方案 | 形态 | 中性度 | 代价 |
|---|---|---|---|
| **A（推荐）几何拟人剪影** | 圆头 + 肩弧，纯描边，无面部特征 | 最高——没有脸就没有性别/年龄/种族/情绪暗示 | 需要内联 SVG |
| B 带表情圆头 | 圆头 + 两点眼 + 微笑弧 | 较高，但"有表情"会带情绪倾向，且接近 emoji 风格 | 同上，更容易显得幼稚 |
| C 「我」字标 | 和助手「AI」形成文字对仗 | 绝对中性 | 零图形，但用户要的是"拟人 logo"，字标不算 |

推荐 **A**：它是"人"这个概念的**最小可辨识形状**——去掉脸、去掉头发、去掉服饰，只留头与肩的轮廓，任何性别、年龄、文化的用户都不会觉得"这画的是别人"。

### 11.3 A 的具体形态

```svg
<svg viewBox="0 0 24 24" fill="none" stroke="currentColor"
     stroke-width="1.7" stroke-linecap="round" aria-hidden="true">
  <circle cx="12" cy="8.4" r="3.6"/>
  <path d="M4.7 20.1c0-4 3.3-6.5 7.3-6.5s7.3 2.5 7.3 6.5"/>
</svg>
```

三条硬约束：

1. **无面部特征**——不画眼、不画嘴。一旦有表情就带情绪，也就不再中性。
2. **肩线不闭合**——底部开口，避免读成"墓碑/证件照"。
3. **纯几何**——不用曲线暗示发型，不做长发/短发，那是性别符号的入口。

### 11.4 与助手头像怎么区分

不靠颜色（色盲不友好），靠**填充 vs 描边**：

| | 助手 | 用户 |
|---|---|---|
| 背景 | 蓝紫渐变**填充**（`:101`） | 面板色 + 1px 边框 |
| 内容 | 「AI」文字，白色 | 人形**描边**，`currentColor` |
| 观感 | 实心亮块 | 空心轮廓 |

一眼就能分出"谁说的"，且在灰度下也成立。

### 11.5 布局影响

- 30px 头像 + 10px gap = 用户气泡**左缩进 40px**，可用宽度相应减少。
- 窄屏（`< 420px`）降到 26px 头像 + 8px gap，避免正文被压太窄。
- 头像 `flex: none`（沿用 `.avatar` 已有规则），不会被长文本挤压变形。
- **附件消息**（只有图/文件、无文字，`:1818` 的 `attRow`）也要有头像——它是"这轮是用户说的"的标识，不该只在有文字时出现。
- **错误消息**（`.msg.error`，`:1820`）已有 `⚠` 头像，不动。

### 11.6 实现位置

| 文件 | 位置 | 改动 |
|---|---|---|
| `src/admin_ui.html` | `:1818` | 用户消息行首插 `<div class="avatar user-avatar">` + `<use href="#ic-user">` |
| `src/admin_ui.html` | `:100-108` | 新增 `.msg.user .avatar` 的描边样式与窄屏尺寸 |
| `src/admin_ui.html` | 模板区（`<body>` 起始处） | 定义一次 `<svg style="display:none"><symbol id="ic-user" viewBox="0 0 24 24">…</symbol></svg>` |

用 `symbol` + `use` 而不是每条消息内联完整 SVG：50 条消息下 DOM 体积差约 10KB，且以后改图形只改一处。

### 11.7 无障碍与主题

- `aria-hidden="true"`：纯装饰图形，读屏不必念。现有助手头像也没加语义，保持一致。
- 颜色用 `currentColor`，由 `.msg.user .avatar { color: var(--fg) }` 决定，**明暗主题自动适配**，不用写两套。
- 图形元素对比度按 WCAG 非文本标准 ≥ 3:1，`--fg` 在 `--panel2` 上足够。

### 11.8 一个顺带发现：要不要顺便改成"用户靠右"

现在用户消息也是**左对齐**（`:106` `text-align:left`、`:108` meta 靠左）。加头像后是"两个人都左对齐，靠头像区分"。

常见 IM 是"用户靠右"（`flex-direction: row-reverse` + 气泡改右上收角）。这属于另一个改法，**本项不动**——保持现状改动最小，也不会和已有的复制/分享按钮定位打架。想改说一声。
