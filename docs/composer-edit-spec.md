## 1. 麦克风挪到发送键左边

**现状**（`src/admin_ui.html:723-729`）：

```
[+] [🎙] [⋯] [ textarea ] [↑]
```

**改为**：

```
[+] [⋯] [ textarea ] [🎙] [↑]
```

- 只动 DOM 顺序，不加包裹层：`#composer` 是 `display:flex`，顺序即布局。
- 麦克风与发送键同为右侧操作组，`gap:8px` 沿用，不再单独写 margin。
- 宽度核算（320px 窄屏）：padding 16+8、`+`34、`⋯`34、`🎙`34、`↑`38、gap 4×8=32
  → 固定部分 196px，输入框剩 124px。可用，但窄屏下把 `+`/`⋯`/`🎙` 统一降到 32px
  （`@media (max-width:420px)`），输入框回到 130px。

**顺带**：`#btn-voice` 现在与 `#btn-attach` 共用一条 CSS（`294` 行），挪位后仍成立，
不改样式表。

## 2. 人类几何 logo 比 AI 大

**现状**（`103-106`、`138-139`）：

| | 圆框 | 内部图形 |
|---|---|---|
| 助手 | 30px | 文字「AI」13px |
| 用户 | 30px | `<svg>` 19px，`stroke-width:1.7` |

**问题**：两者框一样大，用户那边是**细线空心**图形、助手是**实心渐变**圆，
视觉重量反过来——用户头像看起来更小。

**改为**：

| | 圆框 | 内部图形 |
|---|---|---|
| 助手 | 30px（不动） | 「AI」13px（不动） |
| 用户 | **32px** | **21px**，`stroke-width:1.8` |

- 窄屏（`<420px`）：用户 28px / 图形 18px，助手仍 26px。
- 只放大 svg 不放大框不行：30px 框里塞 22px 图形会顶到边，反而更挤。
- 副作用：用户消息行高 +2px。消息是右对齐、助手左对齐，不会出现"两边不齐"的观感。

## 3. 修改 = 打回输入框，发送时才删原消息

**现状**（`2191-2232`）：点「修改」→ 气泡**原地**变 textarea + 「取消 / 保存并重发」，
点保存才截断重发。用户要求改成"打回文本框"。

**改为**：

### 交互流程

1. 点消息「…」→「修改」
2. 原消息内容回填 `#input`，附件一并回填到 `attachments`，光标置末尾，滚到底部
3. 输入区上方出现 **「修改中 · 取消」** chip（复用 `.skill-chip` 版式，橙色描边区分）
4. 用户改完按发送（或 Enter）→ **先删原消息，再正常发送**
5. 取消 / 切换会话 / 新建会话 → 清 chip 与回填内容，**原消息不动**

### 关键设计

- **删除动作推迟到发送那一刻**。点「修改」只做回填，不截断——用户中途放弃不会丢历史，
  这是与现状最大的区别（现状点保存才删，但原地编辑期间界面已经被 textarea 占住）。
- 删除范围沿用 `truncateFrom(c, idx)`：原消息**及其后所有消息**。只删原消息会让后面的
  回答失去对应提问，对话直接断裂。
- 用 `editCtx = { convoId, idx, atts }` 记住来源，发送前校验 `curConvo().id === editCtx.convoId`，
  防止"在 A 会话点修改、切到 B 会话发送"把 B 的消息删了。
- `truncateFrom` 自带越界检查，原消息若已被「重新生成」删掉，`idx` 失效则只发新内容，不报错。

### 要删的旧实现

- `menuEdit()` 里创建 `.edit-wrap` / `.edit-ta` / `.edit-acts` 的整段（`2204-2231`）
- 对应 CSS（`.edit-wrap`、`.edit-ta`、`.edit-acts`，若有）
- `openMsgMenu` 里「修改」的入口不变，仍调 `menuEdit`

### 新增

- `#edit-chip` DOM（在 `#skill-chip` 之后）+ `renderEditChip()`
- `cancelEdit()`
- `sendOrStop()` 发送前插入截断步骤；`sendWith()` 本身不动（它也被重试 / 通话复用）
- 切会话处（`openConvo` / `newChat`）调用 `cancelEdit({ silent:true })`

## 5. 模型按钮往加号边上靠拢

与第 1 项是同一处调整：`⋯` 从"麦克风右边"移到"`+` 右边"，两者直接相邻。

- `+` 与 `⋯` 之间 `gap:8px`，同为 34px 圆形、同款边框 → 视觉上成为一组"输入区左操作"
- 不需要额外 CSS；若希望更像一组，可把两者间距单独收到 6px（`.composer-model{margin-left:-2px}`），
  但默认**不做**，保持与右侧间距一致。

## 6. 打开模型页定位当前模型，删「当前在第 x 页」

**现状**：

- `openModelPicker()`（`3886`）固定 `mpTab="text"`、`mpPages` 全部重置为 1
- 当前模型不在第 1 页时，靠右下角 `#model-jump`「当前在第 N 页 ›」手动跳
- 选中行本身有「当前」徽标 + 左侧 3px 竖条

**改为**：

1. 打开时先算 `modelTabOf(curModel)`，**切到当前模型所在标签**（选了音频模型就落在音频标签，
   不再总是文本标签）；返回空（模型已下架）则退回文本标签。
2. 抽 `mpBuild()`：把 `renderModelList` 里"组装 items → 计分 → 排序 → 搜索过滤"那段
   （`3951-3964`）提取为纯函数，返回 `{ items, rest, autoItem }`。
   `renderModelList` 与 `openModelPicker` 共用，保证"定位用的顺序"和"渲染用的顺序"是同一份。
3. `openModelPicker` 用 `mpBuild()` 算出当前模型在 `rest` 里的下标：
   `mpPages[tab] = Math.floor(idx / MP_PAGE_SIZE) + 1`；当前是「自动」或找不到 → 第 1 页。
4. 删 `#model-jump`：DOM（`1106`）、CSS（`.mp-jump`）、`renderModelList` 里的 jump 段
   （`4019-4031`）。分页条只剩「‹ N / M · 共 K 个 ›」。
5. 定位后不额外滚动：每页 5 条整页可见，选中行自带「当前」徽标。

**取舍**：不记忆"上次停留的页码"。定位的语义是"我现在用的是什么"，每次打开都回到当前模型，
比记住上次翻到哪更有用。
